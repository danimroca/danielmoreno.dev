Case Studies

Three problems I owned end-to-end — the kind of work that doesn't show up in a job title.

Performance · IAM

Keycloak at scale

Baseline user concurrency from Datadog, then load-tested Kubernetes pods to failure to understand capacity and DDoS readiness. A customer onboarding ~2,000 new users didn't break Keycloak itself — it broke the backoffice dashboard's user parsing. Reproducing the load with a different customer's data revealed the document parser crashed on 1,000-page files; I worked with SRE to raise its capacity. Quarterly reviews with customer support kept us ready for large releases and enterprise acquisitions.

Identity · CI/CD

Deterministic SSO in the pipeline

Built Docker-pinned mock SAML and OIDC identity providers so every pipeline started from the same state. A Playwright job then created an organisation with an admin, configured the SSO connector to both mocks via YAML, provisioned new users, and signed in through both SAML and OIDC flows — verifying the full identity path on every run, no drift.

AI · Quality

Guardrails for AI-generated tests

As juniors leaned on AI to write code and tests, I wrote a skill file to steer generation: verify the test path doesn't already exist, focus on critical paths, keep test volume at 10–15% of code lines, and diff coverage before/after. It rejected duplicate paths, backend email checks already covered at the frontend, and admin-gated actions tested as a standard user.

How I run security testing

  • Ticket per finding. Every flagged issue becomes a tracked ticket; the owning dev team fixes it in their own codebase, with my help verifying coverage.
  • False positives are re-tested. Declared FPs get flagged and I re-validate them every couple of months against developer instructions — never mark-and-forget.
  • Clear release blockers. High/critical findings block a deploy, as does anything that could expose user private data (PII).
